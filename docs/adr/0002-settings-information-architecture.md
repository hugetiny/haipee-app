# 2. 设置中心信息架构五级领域重构 (Settings Information Architecture)

* 状态: 已接受 (Accepted)
* 日期: 2026-10-05

## 背景 (Context)

随着 Kazumi 从早期轻量番剧客户端演进为聚合在线播放、全网 BT 资源检索、离线 Aria2 下载与 WebDAV 同步的全功能媒体应用，设置项逐渐增多且散落堆叠在根页面：
- 播放器与弹幕设定、Bangumi / TMDB 刮削设定、在线流媒体插件源、Cardigann 索引器规则设置、Aria2 下载引擎、WebDAV 同步等混合平铺在主页，视觉杂乱且缺乏清晰的职责边界。
- 用户容易混淆“在线视频源插件 (VideoPlugin)”与“全网 BT 资源规则 (Cardigann YAML)”。
- 元数据设置（Bangumi / TMDB）散落在通用与播放之间，缺乏未来支持自定义 API Key、鉴权与偏好语言的扩展空间。

## 决策 (Decision)

我们重构设置中心的信息架构，确立严格的自顶向下五大领域一级分类：

1. **顶级一级分类排序与领域职责**：
   - **`通用与外观 (General & Appearance)`**：置于最顶部，包含主题外观（深浅色/强调色/纯黑）、语言与区域、桌面窗口退出行为、网络代理与 GitHub 加速。
   - **`视听与媒体 (Media & Playback)`**：专注媒体消费体验，下设「播放器设定」、「弹幕设定」、「媒体元数据与刮削 (Bangumi / TMDB)」、「在线视频源插件 (VideoPlugin)」。
   - **`资源检索与下载 (Resource & Download)`**：专注资源获取全流程，下设「全网资源规则 (Cardigann YAML 规则中心与市场)」、「下载引擎 (Aria2 进程、路径与限速)」。
   - **`数据与云同步 (Data & Sync)`**：专注数据安全性，下设「WebDAV 云端备份与同步」、「本地存储与缓存管理」。
   - **`关于与支持 (About & Support)`**：专注应用生命周期，下设「检查更新」、「运行日志与诊断 (Talker)」、「开源许可与社区」。

2. **视听与媒体二级聚合导航页 (`/settings/media`)**：
   - 点击主页的「视听与媒体」后，进入专属二级页面，分类承载播放、弹幕、元数据与在线视频源，杜绝主页过长。

3. **媒体元数据独立设置子页 (`/settings/metadata`)**：
   - 将原散落的 Bangumi 开关、ECH / 镜像网络加速与 TMDB 开关收敛为独立的元数据设置页，并为后续自定义 TMDB API Key、Bangumi 授权登录预留扩展接口。

4. **术语规范与边界划分**：
   - 彻底区分「在线视频源插件 (VideoPlugin)」与「全网资源规则 (Cardigann YAML)」，在文案与说明中明确标注应用场景。

## 后果 (Consequences)

### 正面收益 (Positive)
- **视觉清爽、心智模型清晰**：每个顶级分类职责高度凝聚，用户查找配置更符合直觉。
- **扩展性强**：各模块具备独立二级/三级页面，未来增加画质滤镜、私有站点凭据、Aria2 监控等高级功能时不再破坏主页布局。
- **跨平台一致性**：全平台遵循 Material 3 卡片式导航与 1000px 居中自适应，无溢出风险。

### 潜在代价 (Negative)
- 增加了部分配置项的一层路由跳转（如点击 视听与媒体 ➔ 播放器设定），但换取了极大的整洁度与层级感。
