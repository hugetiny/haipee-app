# 7. 多源元数据资源分类与全网下载联动架构 (Multi-Source Metadata and Resource Catalog Architecture)

* 状态: 已接受 (Accepted)
* 日期: 2026-10-15

## 背景 (Context)

Kazumi 的定位已从单一的“追番客户端”演化为“多品类全网资源索引、下载与流媒体中心”。此前存在以下核心痛点：
1. **一级导航割裂与过度占位**：历史版本中“热门番剧”和“时间表”各自霸占一级主导航，导致全网资源搜索与下载的核心能力被边缘化；同时时间表仅服务于动画排片，占满侧边栏 Rail 空间不合理。
2. **分类混乱与真实接口脱节**：Bangumi (bgm.tv) 官方后端真实包含 5 大独立条目类型：书籍(1)、动画(2)、音乐(3)、游戏(4)、三次元影视(6)。旧实现将影视生硬拼凑在动画(2)的标签过滤中，导致影视分类查询出现空结果，并遗漏了书籍大类。
3. **多站点扩展性缺失**：随着后续计划接入更多元数据源站（如 TMDB、VNDB、豆瓣等），若简单将所有分类平铺在顶部 TabBar，会导致移动端与桌面端视窗严重拥挤变形。
4. **元数据发现与下载检索断层**：在条目详情页，旧版只保留调用网页视频爬虫插件的“开始观看”按钮，在游戏、音乐、图书等非视频分类下完全不可用，未能与已建成的 Cardigann/Torznab 全网种子检索引擎形成闭环。

## 决策 (Decision)

我们决定重构主导航为以「资源分类」为核心的发现中枢，并建立基于 Torznab 工业标准的跨域资源联动架构：

1. **主导航收敛为 5 大高频中枢**：
   - 彻底移除「时间表」作为一级独立导航，主导航 Rail/Bar 收敛为 5 个核心模块：
     1. `资源分类` (`Routes.media` / `Routes.catalog`)
     2. `全网资源` (`Routes.resource`)
     3. `离线下载` (`Routes.download`)
     4. `我的` (`Routes.my`)
     5. `设置` (`Routes.settings`)
   - 「时间表」降级为「资源分类 -> 动画」频道内的快捷操作与顶栏工具，保持功能可用而不占用全局主导航空间。

2. **多源元数据分层架构 (Multi-Source Metadata Provider)**：
   - 将信息站抽象为 `MetadataProvider` 规范，当前以 Bangumi 为默认提供方，底层支持动态注入其他站（如 TMDB、VNDB 等）。
   - **UI 呈现规范 (Option A)**：
     - **第 1 层 (AppBar)**：展示 `资源分类`，并集成紧凑的源站切换器（如 `[ 🌸 Bangumi ▾ ]`），支持动态多站扩展。
     - **第 2 层 (分类单选胶囊)**：由当前源站动态提供各大分类（Bangumi: 动画[2]、影视[6]、游戏[4]、音乐[3]、书籍[1]），单选横向平滑滚动，绝不挤压高度。
     - **第 3 层 (二级细分标签与排序)**：大分类下的细分标签流与排序策略。

3. **Torznab 工业标准作为跨域分类对齐桥梁 (Universal Rosetta Stone)**：
   - 针对各 Cardigann YAML 站点分类各异的问题，利用已建立的 Torznab 标准分类（1000 音频, 2000 电影, 3000 书籍, 4000 游戏, 5000 电视剧, 5070 动画）作为通用中介：
     - `Bangumi type 1 (书籍)` -> Torznab `3000 (Books)`
     - `Bangumi type 2 (动画)` -> Torznab `5070 (Anime)`
     - `Bangumi type 3 (音乐)` -> Torznab `1000 (Audio)`
     - `Bangumi type 4 (游戏)` -> Torznab `4050 (PC/Games)`
     - `Bangumi type 6 (影视)` -> Torznab `2000 (Movies) / 5000 (TV)`
   - 当发起全网搜索时，Cardigann 引擎自动根据各个 `.yml` 规则文件中的 `caps.categorymappings` 将 Torznab 标准 ID 转换为目标站点专有的分类参数（如 nyaa 的 `1_2` 或 dmhy 的 `sort_id=2`），实现 100% 精准对应。

4. **详情页与卡片动作按媒体类型智能聚合（化繁为简，消除双轨制与旧版Kazumi插件搜索）**：
   - **彻底废除左右双按钮分流**：杜绝旧版“全网BT搜索 + 在线观看”同质化双按钮割裂设计，贯彻全应用统一极简交互。
   - **针对动画与影视 (`type: 2 / 6`)**：
     - 底部呈现单一高对比度核心大按钮：`开始观看` (`Key('info_btn_watch_online')`, 图标 `Icons.play_arrow_rounded`)。
     - 点击直接唤起现代化的全网资源聚合与流式播放面板 (`TorrentSearchSheet`)，支持分集筛选、直接在线边下边播与极速离线下载，彻底废除跳转旧版 Kazumi 网页爬虫搜索界面。
     - 详情页顶栏提供辅助动作图标：`全网资源深度检索` (图标 `Icons.travel_explore_rounded`)，直通全网表格。
   - **针对游戏、音乐、书籍 (`type: 4 / 3 / 1`)**：
     - 彻底屏蔽“在线观看”，底部呈现单一加宽的高对比度主按钮：`搜索全网资源` (`Key('info_btn_universal_search')`)，点击直接携带作品名称和单选分类过滤器跳转至全网资源搜索表格。

5. **全网资源搜索过滤器单选联动**：
   - `ResourceSearchContent` 的分类过滤器保持严格单选机制；
   - 从元数据条目跳转时，自动选中对应分类，自动发起并发检索；同时保留 `全部` 选项供用户自由切换。

## 后果 (Consequences)

### 正面收益 (Positive)
- **多站点伸缩自如**：无论后续接入 1 个还是 10 个信息站，页面骨架保持固定两行高度，结构清晰，绝不拥挤。
- **真实数据 100% 对应**：彻底解决此前影视查不出数据的问题，并完整补足书籍大类。
- **全链路闭环**：打通了从“看到一部想玩的游戏 / 想听的专辑 / 想看的动漫”到“一键搜索全网 BT 资源并离线下载”的流畅闭环。
- **导航层级极其干净**：5 个一级模块清晰聚焦，桌面与移动端体验一致。

### 代价与局限 (Negative & Mitigations)
- 需要为 `ResourceSearchPage` 增加路由参数传递（`initialKeyword` 与 `initialCategory`），并通过 Riverpod 状态自动触发首次搜索。
- 部分专精单一类型的 Cardigann Indexer 在跨分类搜索时会跳过或返回空，此为符合预期的正常行为，由多源并发池自然聚合。
